
# Incident Report — Chaos Event
**Date:** 2025-12-02  
**Start:** 13:01:01  
**End:** 13:01:31  
**Severity:** Low  
**Duration:** ~30 seconds  

## Summary
Between **13:01:01 and 13:01:31 MST** on **2025-12-02**, the JWT Pizza Service experienced **internal 500 errors** on `POST /api/order`. These failures were triggered by **Chaos Monkey** from the Pizza Factory service. Error responses included a recovery link and messages like `"chaos monkey"` and `"Failed to fulfill order at factory"`.

However, the expected alert notification did not fire initially because the Pizza Factory alert webhook was misconfigured.  
The webhook incorrectly pointed to the my project’s **regular website URL** rather than the required **Pizza Service URL**:

```
INCORRECT: https://pizza.afield98.click/
CORRECT:   https://pizza-service.afield98.click/
```

After correcting the URL, the alert fired immediately, confirming the alerting system was otherwise functioning correctly.

Impact was limited to simulated traffic and lasted less than one minute. (because it was only received on my end for a brief moment before my 500 error alert went off and I checked the logs)

## Detection
The incident was first visible in logs when `POST /api/order` returned a **500** at:

```
2025-12-02 13:01:01.236
```

Chaos monkey messages also appeared, confirming injected failure.

### Why detection was delayed
Although errors occurred on schedule, **no alert was sent** because:

- The Pizza Factory → Pizza Service webhook URL was wrong.
- Therefore, error notifications never reached the pizza service.

Once I checked JWT Pizza Factory and corrected the URL, the alert fired immediately.

### Improving detection 
- Add a dashboard panel showing Last successful webhook callback.  
- Add startup logging in the Pizza Service confirming the expected alert URL.

## Response
- Investigates missing alert → finds misconfigured webhook  
- Corrects URL → alert fires 
- I checked logs and identifies chaos failures  
- Recovery link visited — chaos ends  

## Root Cause
### Primary
Intentional chaos injection from the Pizza Factory service caused forced failures in the `/api/order` fulfillment pipeline.

### Contributing
The alerting webhook URL in Pizza Service was misconfigured, which prevented the on-call alert from reaching me during the initial chaos window.  
This **did not cause the failure**, but **delayed detection**, increasing time-to-response.

## Resolution
- Chaos event was identified through 500-error logs and factory-returned chaos report URLs.
- Visiting the `followLinkToEndChaos` endpoint immediately halted chaos injection.
- System returned to normal operation with successful order fulfillment.

## Prevention
- Improve alert observability to make misconfigurations visible sooner.
- Add more internal resilience and retry logic for the order → factory call chain.
